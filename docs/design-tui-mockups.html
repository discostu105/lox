Design proposal · lox v0.12

lox tui

A full-screen, keyboard-first, live terminal view of a Loxone installation. It shows what the house is doing, lets you change it, and explains why things happened. Every frame below is a real 120×36 cell grid, so the layouts are exact. Switch themes in the bar. The full spec is in docs/design-tui.md.

Live by defaultValues come from the WebSocket stream. Nothing needs a manual refresh.
One vocabularyEleven action keys mean the same intent on every control type.
Always discoverableThe footer shows what keys do here, ? shows all keys, a lists every action.
SafeLights are instant. Doors ask first. Reboot asks you to type the site name.
ScalesFrom 50 to 2,000 controls: filter, group, collapse noise.

Screen 1 · key 1

Home: how is the house, and does anything need me?

Room cards summarize each room (temperature and trend, lights, blinds, presence). Attention collects everything that needs a person: low batteries, open windows before rain, unlocked doors, available updates. Energy, pinned controls, quick scenes and the live ticker fill the rest.

Screen 2 · key 2

  
Rooms: the control surface

  
Three panes: rooms, the controls in the room grouped by category, and an inspector. The selected blind is moving. The pending spinner turns while the stream reports new positions, and a toast confirms the command. The footer always shows what the action keys do for the selected type.

  
lox tui --screen rooms120×36






  
Overlay · key : or Ctrl-k

  
Palette: go to anything, or run a lox command

  
Plain text searches controls, rooms, scenes, screens and sites with fuzzy matching. Text that starts with a lox verb is parsed by the same clap definitions as the CLI, so the TUI teaches the CLI.

  
lox tui120×36






  
Screen 3 · key 3

  
Events: what just happened, and why?

  
A live feed with follow mode. High-frequency meters collapse into one row (×340), and noisy controls can be muted. Selecting an event shows everything that changed within ±2 s: the door opened, then the motion sensor fired, then the light came on.

  
lox tui --screen events120×36






  
Screen 4 · key 4

  
Energy: where the power goes

  
A flow diagram built from the configured meters. The arrows move at a speed proportional to the power. Below: today's PV curve with the forecast after “now”, and every meter sorted by current power.

  
lox tui --screen energy120×36






  
Screen 5 · key 5

  
System: btop for the Miniserver

  
CPU and heap history, Tree/Air devices sorted problems first, CAN/LAN counters with per-interval deltas, and the log tail. Sub-views ([ ]) add Config history with a semantic diff (via lxir) and firmware update/reboot with typed confirmation.

  
lox tui --screen system120×36






  
Screen 6 · key 6

  
Sites: every Miniserver at a glance

  
One row per lox ctx context, polled lightly while this screen is open. ⏎ switches the whole TUI to that site. C opens a quick switcher from anywhere.

  
lox tui --screen sites120×13






  
Overlays · keys ? and confirm

  
Help and safety

  
The help overlay is generated from the same keymap table that drives dispatch and the footer, so it is always correct. Risky actions ask for confirmation, with No as the default.

Keyboard model

  
One vocabulary, every control type

  
Navigation keys never change the house. Action keys always mean the same intent. The footer shows the concrete effect. A dash means the key does nothing for that type; it stays visible but dimmed.

Visual system

  
Palette tokens

  
Loxone green is the only accent. The other colors carry meaning: state, severity, or energy source. Emoji are not used because their width breaks alignment. Glyphs are single-width Unicode, with an optional Nerd Font set.

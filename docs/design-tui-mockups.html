Design proposal · round 2

lox tui

A full-screen, keyboard-first, live terminal view of a Loxone installation. This round borrows btop's visual language: braille graphs with height gradients, gradient meters, pane titles in notches of the border, and key hints in the focused pane's bottom border instead of a separate footer. Every frame is an exact cell grid, and the theme switcher re-renders every frame. The spec is in docs/design-tui.md.

Live by defaultValues come from the WebSocket stream. Nothing needs a manual refresh.
One vocabularyTwelve action keys mean the same intent on every control type.
Always discoverableThe focused pane's border shows what keys do here, and ? shows all keys.
Explains itselfw shows the logic wiring behind any control, with live values on the wires.
Six widgetsNotched box, meter, dot meter, dot sparkline, braille graph, flow line. Every screen is built from these.

Screen 1 · key 1

Home: how is the house, and does anything need me?

Each room card shows temperature, a dot sparkline of its recent temperature, lights, blinds and presence. Attention collects everything that needs a person. The live ticker fades with age: new events are bright, older ones dim.

Screen 2 · key 2

  
Rooms: the control surface

  
Rooms, the controls in the room, and an inspector. The key hints live in the focused pane's bottom border and follow the selection. For the moving blind, ␣ reads “stop”; for a blind at rest it reads “▲ up” or “▼ down”, so you always know what Space will do before you press it.

  
lox tui --screen rooms120×36






  
Overlay · key w · powered by lxir

  
Wiring: why is this light on?

  
The config's logic around a control, read from the .Loxone file with lxir. Live values come from the stream, because the WebSocket state UUIDs are the block output connectors in the config (checked against a real config: 148 of 148 controls, 25 of 25 rooms). Wires from blocks without a visualization have no live value and are drawn dashed.

Overlay · key : or Ctrl-k

  
Palette: go to anything, or run a lox command

  
Fuzzy search across controls, rooms, scenes, screens and sites. Text that starts with a lox verb is parsed by the same clap definitions as the CLI.

Screen 3 · key 3

  
Events: what just happened?

  
An event-rate graph, then the feed. High-frequency meters collapse into one row, and noisy controls can be muted. Selecting an event shows everything that changed within ±2 s. Events stay in memory only (10k ring buffer), and nothing is written to disk.

  
lox tui --screen events120×36






  
Screen 4 · key 4

  
Energy: where the power goes

  
A flow diagram whose arrows move at a speed proportional to the power. Below it, a mirrored braille graph in btop's net style: PV production above the line, consumption below it, and the forecast in grey after “now”.

Overlays · ? and confirm

  
Help and safety

  
The help overlay is generated from the same keymap table that drives dispatch and the border hints. Risky actions ask first, with No as the default.

Maintainability

  
Six widgets build every screen

  
Each widget is a small ratatui Widget (roughly 50–150 lines). Colors come from theme gradients, so a theme is just data. On terminals without truecolor, gradients fall back to 256 colors, and to solid semantic colors on 16-color terminals.

Keyboard model

  
One vocabulary, every control type

  
Navigation keys never change the house. Action keys always mean the same intent, and the border hint shows the concrete effect. A dash means the key does nothing for that type. w is new in this round.

Visual system · Loxone Night

  
Tokens and gradients

  
Loxone green is the only accent. Semantic colors carry state and severity. Gradients color graphs by height and meters by position, the way btop does, and they are defined per theme.

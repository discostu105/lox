# Lockfile specification (v8)

The lockfile holds the identities between Lox Logic source and the compiled config, like
`terraform.tfstate` or `package-lock.json`. Name it `<module>.lock.json`, next to the module, and
**commit it**: collaborators and CI must produce the same UUIDs.

`compile` writes and reads it. The only supported manual changes are those under *Operations*. Do not
edit fields by hand otherwise: a wrong port UUID silently breaks wire identity.

## Structure

```jsonc
{
  "lockfile_version": 8,

  "target": {                       // informational metadata (nullable)
    "config_version": "17010727",   // ConfigVersion of the last base
    "miniserver_serial": "504F94112233",  // machine id minted into UUIDs;
                                    // also the CLI's --serial fallback
    "source_config_sha256": "…",    // sha256 of the last base's bytes
    "semantic_fingerprint": "…"     // fingerprint of the last output —
                                    // the drift baseline (`loxl drift`)
  },

  "counters": {                     // ControlList Next* counters, monotone
    "next_obj": 202,                // raised by 1 per minted managed object
    "next_const": 1,
    "next_note": 1,
    "next_mem": 1,
    "next_mint": 8                  // minter sequence high-water mark:
                                    // later compiles seed past it (and
                                    // past every locked UUID) so a block
                                    // minted in a second session never
                                    // reuses a (time, sequence) pair.
                                    // Absent until something was minted.
  },

  "objects": {                      // managed blocks: slug → identity
    "beschatten": {
      "uuid": "1ff9b180-0000-0007-ffff504f94112233",
      "type": "And",
      "ports": {                    // EVERY port has a pinned UUID —
        "I1": "…-00ff…",            // wires reference port UUIDs, so
        "I2": "…-01ff…",            // these must never change
        "Q":  "…-02ff…"
      },
      "layout": {                   // drawing rectangle; kept
        "px": 7392, "py": 1080,     // stable so recompiles don't shuffle
        "px2": 8736, "py2": 1776    // the page. Placed by compile when
      },                            // absent; a GUI drag in the base
                                    // replaces it (harvested at teardown).
      "superseded_layout": { … },   // the base's position that the last
                                    // placement (relayout) replaced. A
                                    // base still showing it is stale, not
                                    // a drag. Cleared whenever a base
                                    // position is taken over (the new one
                                    // arrived, or a drag); rewritten by
                                    // every placement. Usually absent.
      "page_uuid": "…",             // <C Type="Page"> the block lives on;
                                    // pinned on first compile (options'
                                    // page) or by adopt (original page).
                                    // Absent in pre-page-pinning locks —
                                    // the next compile fills it.
      "expr_owned": true,           // generated by expression desugaring
                                    //: when the slug vanishes from
                                    // the desugared source, the compiler
                                    // removes it without a `removed`
                                    // statement. Absent = hand-written.
      "states": ["…", "…"]          // the special states (`SpStates=`)
                                    // minted with a new block whose app
                                    // entry names them; written
                                    // while the base lacks the block.
                                    // Absent for most blocks.
    }
  },

  "externals": {                    // resolved externs: slug → pin
    "sonne": {
      "uuid": "20000003-0000-0030-ffff504f94112233",
      "matched_by": "iname",        // "uuid" | "iname" | "title" | "mirrors"
      "title_at_match": "Sonnenschein",   // for humans reading diffs
      "iname_at_match": "VI3"
    }
  },

  "extern_wires": [                 // <In> elements WE added to extern
    { "from": "<port-uuid>",        // ports; sorted, deduplicated.
      "to":   "<port-uuid>" }       // Teardown removes exactly these.
  ],

  "set_originals": {                // extern port uuid → Def value before
    "<port-uuid>": "100"            // our first assignment (null = attr
  },                                // was absent). Restored when the
                                    // assignment leaves the source.

  "attr_claims": {                  // attribute claims on externs (v3),
    "<object-uuid>": {              // omitted when empty
      "room": {                     // "title" | "room" | "category"
        "original": "<place-uuid>", // value before the claim (restored)
        "written": "<place-uuid>",  // value the claim wrote (a title, or
                                    // the Place/Category UUID)
        "followers": [              // room/category: descendants that
          "<object-uuid>"           // carried `original`; title: the refs
        ]                           // of the object. Rewritten with
                                    // it; omitted when empty
      }
    }
  },

  // Removal tombstones (v2): everything the compiler *withdrew*
  // stays remembered until a compile sees a base that no longer carries
  // it — so recompiling against a base from before the withdrawal was
  // pushed still produces the correct output (a lock fixpoint), instead
  // of passing the withdrawn object/wire/value through unmanaged.
  "removed": {                      // deleted blocks, keyed by object UUID
    "<object-uuid>": {              // (a slug may be reused while its old
      "slug": "beschatten",         // removal is still pending)
      "type": "And"
    }
  },
  "removed_wires": [                // withdrawn extern wires; a base still
    { "from": "<port-uuid>",        // carrying one loses it again, a base
      "to":   "<port-uuid>" }       // without it retires the entry
  ],
  "removed_sets": {                 // withdrawn Def writes: port uuid →
    "<port-uuid>": {
      "original": "100",           // what to restore (null = attr absent)
      "written": "70"              // the value we had written — the marker
    }                              // by which a pre-push base is
  },                               // recognized; any third value means
                                   // another writer took over (retires)
  "removed_attrs": {               // withdrawn attribute claims:
    "<object-uuid>": {             // same shape as attr_claims; restored
      "title": {                   // while the object still shows
        "original": "Alt",         // `written`, retired otherwise
        "written": "Neu"
      }
    }
  },
  "pages": {                       // pages the compiler created:
    "Küche Logik": "21879f0f-0000-0048-ffff504f94112233"
  },                               // title → page UUID, while the
                                   // `page … (room: …)` statement lives
  "moods": {                       // light moods the compiler minted
    "<controller-uuid>": {         //: name → mood UUID, until a
      "Lesen": "21883d91-0000-009d-ffff504f94112233"
    }                              // base carries the mood
  },
  "rules": {                       // named Automatic Designer rules
    "regel_mittag": "2188e51a-0000-0074-ffff504f94112233"
  }                                //: slug → rule UUID, while the
}                                  // `rule <slug> "Name"` declaration lives
```

Serialization is stable: `serde_json` pretty-printing over `BTreeMap`s,
trailing newline. Recompiling with unchanged inputs reproduces the file
byte-for-byte, so lockfile diffs in review always mean something.

## Invariants (enforced by `compile`)

1. A slug present in `objects` is never re-minted; the recorded object *and
   port* UUIDs are emitted exactly.
2. A new slug mints UUIDs and appends them here before the output is
   produced.
3. A slug in `objects` but missing from source aborts the compile, unless the removal is explicit:
   a `removed <slug>` statement, `allow_removals`, or `Lockfile::remove_object`, which forgets the
   block and leaves it unmanaged
   ([decision 0006](decisions/0006-removal-trichotomy.md)). An `expr_owned` entry needs none of
   these, since editing the owning expression is the authorization.
4. `counters` never decrease. They take the maximum of the base document's counters and advance by
   one per created object.
5. `externals` entries are dropped when the extern leaves the source,
   and replaced when its `uuid:` matcher names a different object than
   the pin — a title/iname pin survives renames of its object;
   `extern_wires`, `set_originals` and `attr_claims` are rebuilt each
   compile from what the source actually declares (teardown first, so
   nothing leaks). A claim's followers are restored only while they still
   show the written value — a follower changed in Loxone Config keeps the
   GUI's value and drops out of the list.
6. Withdrawals leave tombstones: a block, extern wire, Def write, or
   attribute claim the compiler stops managing moves to `removed` /
   `removed_wires` / `removed_sets` / `removed_attrs` (if the base
   actually carried it) and keeps being
   deleted/restored on every compile until a base without it is seen —
   then the entry retires on its own. The compile → push → download
   window is therefore a lock **fixpoint**: the committed state recompiles
   byte-identically before and after the push.
7. A `pages` entry is the identity of a page the compiler created.
   A base without that page gets it again under the same UUID; a base
   whose page so identified carries another title (renamed in Loxone
   Config) aborts the compile instead of creating a second page. The
   entry is dropped with its statement (or its `room:`); the page itself
   is never deleted.
8. A `moods` entry is the identity of a light mood the compiler minted
  : a recompile against a base without it mints it under the same
   UUID. The entry retires once a base carries the mood (its `UUID=` is
   then the controller's own) or the claim no longer adds it.
9. A `rules` entry is the identity of a named rule, found by
   name in the base or created by the compiler: a base without that UUID
   gets the rule again under it, one that carries it has its `Title=` and
   payload `name` set to the source's name. The entry is dropped with its
   declaration (the rule itself is never deleted) and follows the slug
   through `loxl rename`.
10. Identity is unique: a base whose `<C>`/`<Co>` UUIDs repeat is refused,
   and an output that would repeat one is never returned.

## Operations

| Task | How |
|---|---|
| stop managing a block (keep its XML) | `Lockfile::remove_object(slug)` |
| rename a slug, keep identity | `Lockfile::rename_object(old, new)` |
| delete a block from the config | recompile with `allow_removals` |
| adopt a different Miniserver | new lockfile (UUIDs embed the machine id) |

After a compile **error**, discard the in-memory lock and reload it from disk: `compile` may have
advanced it before failing. The CLI saves the lock only after a successful compile.

## Versioning

`lockfile_version` is checked on load, and unknown versions are refused rather than reinterpreted. An
older lock loads with the newer fields empty. Saving always writes the current version, so an older
binary refuses the lock instead of silently dropping state it does not know.

| Version | Adds |
|---|---|
| v1 | `target`, `counters`, `objects`, `externals`, `extern_wires`, `set_originals` |
| v2 | removal tombstones: `removed`, `removed_wires`, `removed_sets` |
| v3 | attribute claims on externs: `attr_claims`, `removed_attrs` |
| v4 | `superseded_layout` on objects |
| v5 | `pages`: pages the compiler created |
| v6 | `moods`: light moods the compiler created |
| v7 | `rules`: named Automatic Designer rules |
| v8 | `states` on objects: the special states of a new block |

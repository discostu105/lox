# D85: `defaults <Type>(…)` states a type's shared parameters once

Status: accepted (2026-11-01)

## Context

Periphery blocks repeat the same parameters. In the r50 house config, 136 `ModbusASensor` blocks each
write the same polling cycle, command, value range and send times; only the address, data type and
scale differ. The file is two thirds repetition, and the value that matters on a block (the one that
differs) is hard to spot. A template does not fit: it would wrap every sensor in an instance, re-key
its lock entry and hide a plain block behind a call. The repeated values are not logic, just the
type's house style.

Decompile also wrote time values as raw seconds (`Delay: 10800`), and grouped the `<-` wires onto an
extern by source order, so the wires into one jalousie stood far apart.

## Decision

**`defaults <Type>(Port: value, …)` gives every managed block of the type the ports it does not
bind.** Expansion applies it after templates are stamped out, so template body blocks take it too,
and then drops the statement. The compiler never sees it, so the output is byte-identical to writing
the values on each block. Blocks generated by expressions and named signals take none: their
bindings come from the operands.

**Values only.** A wire, an expression or a label is refused: a default that wires a block reads like
logic hidden at the top of a file. `device:` and `mirrors:` are refused because they say which object
a block is.

**One per type, top level only.** Two statements for one type would raise the question which wins.
A template body would make the default depend on instantiation. Both are errors.

**A block's own binding wins in any form.** A wire into a defaulted port replaces the default, as a
value does. There is no opt-out spelling: a block that wants the port's built-in value writes it.

**Factoring in decompile and adopt.** For a type with at least three managed blocks, a port becomes a
default when every block binds it to a value and more than half share one value (the first to the top
count). Three blocks keep the statement from replacing a pair of lines; the majority keeps it from
standing for an arbitrary pick. Blocks with a trailing comment on that binding keep it.

**Locality: one page per factored type.** Only a type whose blocks all sit on one page (or all in the
periphery) is factored, and its statement goes at the top of that page's file. Defaults written in
one file and taking effect in another would make a file's meaning depend on its neighbours, which
[D84](0084-page-per-fragment.md) removed for `page`. The statement itself is module-wide, so a hand
written one may still serve several files; decompile does not write one.

**`adopt --uuid` respects the module's defaults.** A binding equal to the default is dropped. A
block that leaves a defaulted port unset is refused: adopting it would set that port. The error says
to take the port out of the `defaults` statement or bind it on the other blocks.

**Unit suffixes in decompile.** A port documented in seconds or minutes gets the largest of `h`,
`min`, `s`, `ms` that gives a whole number (`10800` → `3h`, `0.5` → `500ms`), and only when scaling
it back reproduces the stored digits. Zero stays bare. Undocumented ports stay bare: the unit is not
guessed.

**Wire grouping.** Extern wires are emitted grouped by target object (first appearance), then by
port, keeping their relative order. Wire order does not affect the output bytes.

**Lint.** `unused-default` reports a statement no block takes: no block of the type, or every block
binds the port.

## Rejected

- **Templates for repeated periphery.** They re-key lock entries (`x` → `inst_x`) and turn a plain
  block into an instance. The r50 jalousie template stays a template: it already states each shared
  value once, and turning it into `defaults AutoJalousie` would move lines without saving any and
  re-key 15 lock entries.
- **Defaults scoped to a page or a file.** A type's house style is module-wide, and the locality
  rule in decompile gives the same reading without a second scope rule.
- **Wires in defaults.** See above.
- **Factoring the most common value below a majority.** The statement would name a value that most
  blocks override.
